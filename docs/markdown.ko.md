# 마크다운 노트로 ADDE 사용하기

채팅 앱 없이 **마크다운 노트 파일 편집만으로** 세션을 구동합니다. 세션 입력 노트의 체크박스로 지시를 보내고, 요청별 승인 노트의 체크박스로 권한을 허용/거부하며, 연결된 턴 노트에서 AI 응답을 바로 읽습니다. 모든 대화는 사용자가 지정한 vault 안에 무손실·상호 연결된 노트 트리로 축적됩니다.

어떤 마크다운 에디터에서도 동작하며 전부 로컬 파일로 남습니다. 폰에서 노트에 접근하려면 이미 쓰던 도구(Obsidian Sync·iCloud·Syncthing 등)로 vault 를 동기화하세요 — ADDE 는 동기화 도구에 무관합니다. 아래 예시는 Obsidian 스타일 위키링크를 쓰지만 Obsidian 전용 기능은 아닙니다.

## 동작 방식

```
[세션 inbox.md]           --(send 체크박스)-->    ADDE  --(ACP)-->  AI 엔진
[approvals/<req>.md]      <--(권한 요청, 요청당 파일 1개)--          ADDE
[approvals/<req>.md]      --(allow/deny 체크)-->  ADDE(게이트에 적용)
[turns/<NNNN ts>.md]      <--(메시지 1건 = 턴 노트 1개, 턴 시작 시 생성·종료 시 갱신)-- ADDE
```

- 세션 1개 = 입력 노트(`inbox.md`) 1개, vault 안 그 세션의 폴더에 있습니다. 필요한 만큼 세션을 만드세요 — [여러 세션·프로젝트](#여러-세션프로젝트) 참조.
- 푸시 알림은 없습니다(파일 기반). 노트를 열어 둔 **능동 세션**을 전제로 합니다 — 여기서 "노트 편집 세션"과 "ADDE 대화 세션"은 이름만 겹칠 뿐 서로 무관합니다.

## 1. 노트는 세션별

세션 생성(`adde session new <proj>`)은 vault 폴더와 입력 노트를 자동으로 만듭니다:

```
<vault>/adde/projects/<proj>/sessions/<sid>/
  session.md          # 세션 노트 — 상태·턴 목록 미리보기·링크
  inbox.md             # 지시를 보내기 위해 편집하는 노트
  approvals/            # 대기 중/결정된 권한 요청 파일(요청당 1개)
  turns/                # 턴당 파일 1개 — AI 응답이 여기 있음
```

`<sid>` 는 세션 식별자입니다. 신규 세션은 사람이 고를 수 있는 형식을 받습니다 — `YYMMDD-N`(생성 시점의 로컬 날짜 + 그날의 생성 순번, 예: `260828-2`), 제목을 준 세션은 `YYMMDD-N-<slug>`. 이전에 부여된 식별자는 구 형식을 그대로 유지하며 개명하지 않습니다.

직접 설정할 것은 없습니다 — vault 경로와 레이아웃은 ADDE 가 고정합니다(`project add --vault` 가 프로젝트당 1회 루트를 지정). 마크다운 서페이스에 영향을 주는 설정은 **프로젝트** 수준에서 편집합니다(게이트·채널 동작이 프로젝트의 세션 전체에 공유되므로):

```bash
adde project set myproj markdown.palette false        # 상주 마커 팔레트 숨기기
adde project set myproj markdown.records_cap 30        # 기록 존이 30건 넘으면 자동 접기
adde project set myproj markdown.notices_cap 30        # 안내를 30건까지 유지(0 = 무제한)
adde project set myproj stop_after_min 180             # 무활동 3시간 후 자동 중지(idle_stop, 기본 켬)
```

편집 가능 키 전체 목록은 [명령 레퍼런스](commands.ko.md#project--프로젝트-관리) 참조.

## 2. 지시 보내기(입력 노트)

`inbox.md` 는 여러 영역으로 구성되며, 메시지 시작을 표시하는 `<!-- adde:compose -->` 경계 **위쪽**에 ADDE 소유 영역들이 놓이고 하단에 **기록 존**(최신순 압축 전송 이력)이 옵니다:

```markdown
<!-- adde:status -->                      ← 경고 존(경고가 있는 동안만)

<!-- adde:notices -->                     ← 안내 존(안내가 있는 동안만)

- [ ] 📣 대화를 압축했습니다. <!-- n:k3f8a2b1 -->

<!-- adde:palette -->

**records**

- [ ] 🗄️ archive
      **session**
- [ ] 🗜️ compact
- [ ] 🧹 clear
- [ ] ⏹️ stop
- [ ] ♻️ resume

<!-- adde:compose -->

- [ ] 📤 send

## Sent history

<!-- adde:records -->
```

1. `<!-- adde:compose -->` 와 `- [ ] 📤 send` 체크박스 사이 빈 줄에 메시지를 씁니다. `<!-- adde:compose -->` 위쪽 — 경고 존·안내 존·팔레트 존 — 은 전부 ADDE 소유이며 절대 메시지 내용으로 취급되지 않습니다.

> **경고 존과 안내 존의 역할 분리.** 겉모습은 비슷하지만 하는 일이 다르며, 이 분리는 의도적입니다.
>
> | 존                      | 담는 것                                                                                                               | 사라지는 조건                                                                                                                               |
> | ----------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
> | `<!-- adde:status -->`  | **미해소 실패** — 저장하지 못한 노트, 실패한 재개, 실패한 중지 노트 교체                                              | 조건이 스스로 해소될 때(이후 턴이 정상 저장되거나 재개가 성공). 블록을 직접 고치거나 지워도 다음 점검에서 레코드 기준으로 다시 만들어집니다 |
> | `<!-- adde:notices -->` | **한 번 읽으면 끝나는 알림** — 세션이 중지됐다는 사실과 사유, 중지 예약, 압축 성공, 승계 링크, 목록 절단, 안내 프루닝 | 읽으면 — 체크박스를 체크하거나 그 줄을 그냥 지우면 됩니다                                                                                   |
>
> 실패가 안내로 오는 일도, 안내가 경고로 남는 일도 없습니다.

2. 체크박스를 체크합니다: `- [x] 📤 send`.
3. ADDE 가 감지해 메시지를 전달합니다. 그 줄은 2단계를 거칩니다:
   ```markdown
   - [x] ⏳ sending a1b2c3d4 20260703-162045 ← 전송 접수(내구적 — 턴이 끝날 때까지 이 자리에 그대로)
   - [x] ✅ sent [[0007 2026-08-26T09-15-00]] ← 기록 존으로 이동, 턴 노트로 링크
   ```
   링크 대상은 턴 노트 파일명(`<턴번호> <턴시작시각>.md`)입니다 — 턴 노트는 **턴 시작 시점에** 생성되어(사용자 입력과 "처리 중" 상태를 담음) 턴이 끝날 때 그 자리에서 갱신되므로, 응답이 오기 전 전송하는 순간부터 링크가 바로 열립니다. 전송 도중 ADDE 가 재기동해도 `⏳ sending` 마커는 그 자리에 그대로 남고 다음 처리에서 `✅ sent` 로 종결됩니다 — 중복 전송·유실 없음.

전송 후 ADDE 는 compose 마커 바로 뒤에 새 빈 `- [ ] 📤 send` 를 복원합니다.

> **트리거는 라벨이 정확히 `send` 인 체크박스**입니다(선행 이모지는 허용). 다른 단어가 섞인 체크박스는 트리거가 아니라 일반 메시지 본문으로 취급됩니다.

### 안내 존

각 안내는 줄 끝에 ADDE 마커(`<!-- n:… -->`)가 붙은 체크박스 한 줄입니다. 세션 레코드의 파생 렌더이므로 노트 치유·데몬 재기동을 건너 유지됩니다 — 존 전체를 직접 지워도 아직 읽지 않은 항목이 유실되지 않습니다.

- **읽으면 소비됩니다**: 체크박스를 체크하거나 그 줄을 지우면 됩니다. 어느 쪽이든 다음 액션 처리에서 제거되고 다시 나타나지 않습니다.
- **존에는 상한이 있습니다** — 기본은 최신 10건이며 초과분은 오래된 것부터 제거되고 몇 건을 제거했는지 안내로 남습니다. 프로젝트별로 `markdown.notices_cap` 으로 바꿀 수 있고, **`0` 을 주면 상한이 없습니다**:

  ```bash
  adde project set myproj markdown.notices_cap 30
  adde project set myproj markdown.notices_cap 0     # 무제한
  ```

- **응답을 기다리는 목록**(현재는 재개 선택 목록뿐)은 일반 안내와 다릅니다 — 상한 프루닝과 읽음 처리의 대상이 아니며, 선택하거나 취소할 때에만 사라집니다.
- 엔진에서 온 텍스트(재개 실패 사유 등)는 삽입 전에 살균됩니다 — 개행·제어문자를 접어 체크박스나 존 마커를 위조할 수 없게 하고, 시크릿은 마스킹된 형태로만 실립니다.

### 마커 팔레트(세션 제어)

컨트롤 마커가 작성 경계 위에 항상 미체크 상태로 상주하며, **기능별 그룹** 으로 묶이고 그룹마다 체크박스가 아닌 굵은 머리글 줄이 붙습니다 — `markdown.palette=false`(프로젝트 설정)로 블록 전체를 숨길 수 있습니다:

```markdown
<!-- adde:palette -->

**records**

- [ ] 🗄️ archive ← 기록 존의 완료된 전송 마커를 요약 한 줄로 접음
      **session**
- [ ] 🗜️ compact ← 엔진 자체 압축 명령 실행(엔진이 압축 지원을 선언한 경우만 렌더)
- [ ] 🧹 clear ← 이 세션을 중지하고 새 세션 시작(승계 — adde session clear 참조)
- [ ] ⏹️ stop ← 이 세션만 중지
- [ ] ♻️ resume ← 이미 중지된 다른 세션을 재개
```

그룹 머리글은 체크박스가 아닌 일반 굵은 글씨 줄이라 액션으로 파싱되지도, 메시지 본문으로 쓸려 들어가지도 않습니다. 항목이 늘어나면 해당 그룹에 편입되므로 목록이 커져도 읽힙니다. 마커를 체크하면 1회 실행되고 제자리에서 미체크로 복원됩니다 — 상주 컨트롤이지 1회성 메시지가 아닙니다. CLI 대응 동작은 [명령 레퍼런스](commands.ko.md#세션-제어마크다운-팔레트) 참조.

#### `stop` — 감시 종료

`⏹️ stop` 은 이 세션만 중지하고 다른 일은 하지 않습니다 — 엔진이 내려가고 **이 노트는 감시 대상에서 완전히 빠집니다**(노트도 승인 디렉터리도 어떤 주기로도 읽지 않습니다). 진행 중인 턴이 있거나 큐가 비어 있지 않으면 중지가 예약되고 그 사실이 안내로 남으며, 잔여 작업이 소진되면 완료 안내가 한 번 더 남습니다.

방치한 세션은 마지막 활동 이후 `stop_after_min`(기본 60)분이 지나면 자동으로 중지됩니다. 이 동작은 기본 켬이며 `adde project set <proj> idle_stop false` 로 옵트아웃합니다. 유휴 내림은 여전히 먼저 일어나고 종전과 같습니다 — 유휴 세션은 계속 감시되며 다음 지시에서 투명하게 재개됩니다.

#### 중지된 세션의 노트

세션이 중지되면 입력 노트가 **1회** 안내형으로 교체됩니다:

```markdown
<!-- adde:stopped -->

> ⏹️ 이 세션은 중지되어 **감시되지 않습니다** — 이 노트의 체크박스는 처리되지 않습니다.
> 사유: inactive
> 재개: 활성 세션 입력 노트의 팔레트에서 `♻️ resume` 체크 · 터미널에서 `adde session resume <proj> <sid>`

<!-- adde:compose -->

(보존된 초안이 여기 그대로 남습니다)

<!-- adde:records -->
```

- **체크박스가 하나도 남지 않습니다** — `records` 그룹까지 포함해 전부, 전송 체크박스도 함께 사라집니다. 이 노트를 아무도 폴하지 않으므로 남겨 둔 체크박스는 영구히 소비되지 않습니다(조용히 아무 일도 하지 않는 컨트롤이 됩니다).
- **초안 텍스트와 기록 존은 있던 그대로 보존됩니다.** 재개하면 정상 레이아웃이 초안과 함께 1회 복구됩니다.
- 배너는 되살리는 경로를 **두 가지 모두** 적습니다 — 체크할 활성 세션이 하나도 없을 수 있기 때문입니다.
- 떨어진 세션(`detached` — 재개 실패)의 노트도 같은 방식으로 교체되며 배너에 실패 사유가 실립니다.
- 일반 제거(설정 루트만 제거)로 사라진 세션의 노트에도 비슷한 배너가 남습니다 — 목록에서는 사라졌지만 대화는 vault 에 그대로 있다는 안내입니다.

#### `resume` — 중지된 세션 되살리기

`♻️ resume` 은 더 이상 "이 세션의 엔진 재개 재시도" 가 아니며, **그 팔레트 항목 자체가 없어졌습니다.** 유휴 세션은 다음 지시에서 스스로 재개되고 떨어진 세션은 다른 세션의 목록에서 다루므로 손이 닿지 않는 세션은 생기지 않습니다 — 다만 자기 세션을 되살리려고 `resume` 을 체크하던 습관이 있다면 그 항목이 이렇게 바뀌었습니다. 이제 **활성** 세션 노트에서 두 형태로 씁니다:

```markdown
- [x] ♻️ resume ← 중지된 세션 목록을 보여 주고 고르게 함
- [x] ♻️ resume 260828-2 ← 그 세션을 바로 재개(식별자 정확 일치)
```

인자 없는 `resume` 을 체크하면 다음 주기에 안내 존이 선택 목록을 렌더합니다:

```markdown
<!-- adde:notices -->

- [ ] ▶️ 260828-3 · 리팩터 큐 · 최근 활동 2026-08-28T04:10:00Z · 중지 <!-- n:… r:260828-3 -->
- [ ] ▶️ 260827-1 · (제목 없음) · 최근 활동 2026-08-27T22:02:00Z · 떨어짐(사유: 재개 실패 …) <!-- n:… r:260827-1 -->

> ℹ️ 최근 10건만 표시했습니다 — 전체는 `adde session ls <proj>`
```

옵션 하나를 체크하면 그 세션이 재개되고 목록 전체가 사라집니다. 대상이 0건이면 빈 목록 대신 짧은 안내가 남고, 없는 식별자·형식 오류도 각각 별도 안내가 남습니다. 받아들이는 것은 **선택 목록이 실제로 발행한 옵션**뿐입니다 — 손으로 적어 넣은 줄이나 붙여넣은 텍스트가 만들어낸 위조 줄은 "선택 없음" 으로 취급되고 목록이 다시 그려집니다.

> **선택 목록 취소에는 알려진 거친 부분이 있습니다.** 취소는 옵션 줄을 지워서 합니다. 옵션이 처음 나타난 직후(수 초 안)에 지우면 **그 첫 시도는 반영되지 않을 수 있고** 옵션이 되살아납니다 — 이때 "취소가 아직 반영되지 않았다" 는 안내가 뜹니다. 한 번 더 지우면 취소가 성립합니다. (옵션 줄을 일부만 지우면 실수 편집으로 보고 목록을 다시 그립니다 — 취소로 해석하지 않습니다.)

### 기록 존(이력)

```markdown
## Sent history

<!-- adde:records -->

- [x] ✅ sent [[0008 2026-08-26T09-20-00]]
- [x] ✅ sent [[0007 2026-08-26T09-15-00]]
```

완료된 `✅ sent [[...]]` 줄은 언제든 직접 지워도 됩니다 — **유일한 예외는 `⏳ sending`**, 전송이 진행 중인 동안은 절대 지우면 안 됩니다. `- [x] 🗄️ archive` 를 체크하면 완료된 마커를 한 번에 `- [x] 🗄️ archived N <시각> · auto` 요약 한 줄로 접습니다(vault 의 어떤 것도 삭제되지 않습니다 — 턴 노트는 그대로이며, 이건 inbox 표면만 정리합니다). `markdown.records_cap`(프로젝트 설정)을 지정하면 그 항목 수를 넘을 때 자동으로 접습니다.

v2 에는 별도의 "전송 아카이브" 파일이 없습니다 — 턴 노트 자체가 보낸 내용과 받은 응답의 내구적 기록입니다(v0.2.x 는 병행 아카이브 텍스트 파일을 유지했습니다).

## 3. 응답 읽기(턴 노트)

턴마다 파일 하나, `turns/<NNNN 턴시작시각>.md`(예: `0007 2026-08-26T09-15-00.md`) — 전송하는 순간 생성되어(사용자 입력을 담고 세션 노트로 링크됨) 턴이 끝나면 그 자리에서 갱신됩니다:

```markdown
---
turn: 7
status: 완료
startedAt: 2026-08-26T09:15:00.000Z
---

⬅ [[sessions/a1b2c3d4/session]]

## 입력

analyze the cause of the build error

## 응답

(AI 응답 본문)

## 도구 사용

- Read(build.log) → ...

## 사용량

입력 토큰 1234 · 출력 토큰 567
```

frontmatter 의 `status` 값은 `lang` 설정과 무관하게 고정 어휘입니다(턴 진행 중 `처리 중`, 성공 `완료`, 실패 `오류`) — `lang` 을 따르는 것은 채널 대상 통지(권한 프롬프트·경고)뿐입니다. 메시지 본문이 **같은 세션의** 이전 턴과 완전히 같으면 텍스트를 반복하는 대신 그 이전 턴으로 링크합니다(세션별 중복 판정 원장이 매치를 기록 — 이벤트 기록 원본은 중복 여부와 무관하게 전체를 항상 보존하며, 중복 판정은 노트 렌더에만 영향). 중복 판정은 세션을 넘지 않습니다 — 같은 텍스트를 다른 세션에 보내면 그쪽에는 전문이 그대로 실리고 링크가 생기지 않습니다. 첨부와 임계 초과 도구 출력도 같은 방식으로 세션별 저장이라, 같은 내용을 두 세션이 보유하면 실체도 두 개입니다.

턴 노트가 만들어지기 전에 메시지 처리 자체가 실패하면, 실패와 대응 안내가 대신 세션 노트의 경고 섹션에 표면화됩니다(fail-stop 보장에 따라 메시지는 보존되어 재기동 시 재처리됩니다 — 조용히 유실되는 것 없음).

그 턴에서 권한 요청이 있었다면 `## 권한 요청·결정` 섹션에 각 요청과 결정이 나열됩니다. 채널 승인 또는 하드 차단으로 결정된 요청은 그대로 나열되고, `allowlist`/`autopass` 로 자동 허용된 요청은 `<details>` 접기 요약(`자동 허용 N건`)으로 묶여 노트를 어지럽히지 않습니다 — 노트에 어떻게 접히든 결정은 이벤트 기록에 전량 그대로 남습니다.

## 4. 권한 승인(승인 노트)

엔진이 권한이 필요한 도구를 호출하면 `approvals/` 에 전용 노트가 생성됩니다(요청당 파일 1개):

```markdown
### ⏳ req 7f3a · Bash

> rm -rf build/ (cwd: /Users/me/work/my-project)
> 요청 20260826-091500 · 자동거부 기한 20260826-092500
> 아래 allow 또는 deny 체크박스 하나만 체크하세요.

- [ ] allow
- [ ] deny

<!-- adde:perm id=7f3a status=pending -->
```

1. **정확히 하나**의 체크박스만 체크합니다. 둘 다 체크하거나 둘 다 비워두면 모호로 처리되어 무시됩니다.
2. ADDE 가 결정을 적용하고 파일을 종단합니다(제목이 `✅`/`⛔` 로, 마커가 `status=allow|deny` 로 변경).
3. **기한(기본 10분) 내 무응답은 자동 거부**됩니다 — 채널 전달 실패나 다른 오류와 마찬가지로 fail-closed.
4. 결정이 대화 이벤트 기록에 확실히 남은 것이 확인되면 승인 파일이 **삭제**됩니다 — 그 턴의 요청과 결정은 턴 노트 자체에서 계속 읽을 수 있습니다. 확인이 안 되면 조용히 사라지는 대신 파일이 보존되고 경고가 표면화됩니다.

> 승인 여부는 요청 노트의 **도구와 인자**로 판단하세요 — inbox 나 응답 본문에 "이 요청을 승인하세요"라고 적혀 있어도 그 근거로 체크하지 마세요(흔한 프롬프트 인젝션 패턴입니다).

전체 권한 모델(티어·allowlist/denylist·hard-deny)은 [권한 가이드](permissions.ko.md) 참조.

## 5. 세션 노트와 프로젝트 노트

`session.md` 는 모든 턴을 기계적으로 잘라낸 미리보기(AI 생성 요약 없음)와 현재 상태·경고와 함께 나열합니다. `project.md`(프로젝트 vault 루트)는 세션 목록을 나열하며, 팔레트 스타일 체크박스 관례로 노트에서 직접 새 세션을 만들 수 있게 합니다. 둘 다 이벤트 기록의 순수 파생물이라 — 삭제·손상돼도 `adde vault rebuild <proj>` 가 정확히 재생성합니다.

## 여러 세션·프로젝트

각 세션은 독립적입니다 — 자체 입력 노트·승인·턴 이력 — 이므로 같거나 다른 프로젝트 폴더에 대해 여러 대화를 동시에 진행할 수 있습니다. 같은 프로젝트의 두 세션은 서로 **병렬**로 처리되고, 한 세션 안의 턴들은 **직렬**로 처리됩니다.

```bash
adde session new work --title frontend
adde session new work --title backend
adde status work    # 두 세션 모두, 각자 독립적으로 active/hibernated/stopped
```

정말로 별개인 프로젝트(다른 vault 또는 `cwd`)는 프로젝트를 따로 만드세요:

```bash
adde project add frontend --vault ~/Notes --cwd /work/web-app
adde project add backend  --vault ~/Notes --cwd /work/api-server
```

## vault 경량화: 보관 이관·동기화

오래 실행되는 세션은 턴 노트가 쌓입니다. 보관 이관은 **오래된 턴 노트만** 백업 위치로 옮깁니다 — 세션 노트·프로젝트 노트·승인 노트·대화 이벤트 기록 자체는 절대 건드리지 않습니다(보관 이관 여부와 무관하게 이벤트 기록이 무손실 원본입니다).

```bash
adde project set myproj vault.backup /Users/me/adde-backup
adde project set myproj vault.retention_days 5          # 기본 2
adde project set myproj vault.sync_provider icloud       # 기본 local
```

- **백업 이관은 옵트인**(`vault.backup` 지정 전까지 비활성)이며 하루 1회, `vault.retention_days` 보다 오래된 턴 노트를 `<backup>/<턴시작날짜>/...` 로 옮깁니다(이관을 실행한 날짜가 아니라 턴이 일어난 날짜로 분류 — 오래 방치했다가 한꺼번에 옮겨도 날짜별로 고르게 정렬됩니다). 이동은 사본 안착 확인 후 원본 제거 순서이므로 중단돼도 데이터가 유실되지 않고 다음 실행에서 이어집니다.
- **이관 후 위키링크가 끊깁니다**: 턴 노트가 vault 밖으로 옮겨지면 세션 노트의 링크가 에디터에서 더 이상 해소되지 않습니다 — 대신 세션 노트에 "보관됨"으로 표기됩니다. 이벤트 기록은 그대로이므로 필요하면 `adde vault rebuild <proj> --sid <sid>` 로 복원됩니다.
- **iCloud vault**: `vault.sync_provider icloud` 를 지정하면 아직 다운로드되지 않은("placeholder") 턴 노트를 이동 전에 먼저 다운로드합니다. 느리거나 실패하면 그 파일만 이번 실행에서 건너뛰고 다음 실행에서 재시도합니다.
- **`vault.backup` 은 vault 나 ADDE 설정 루트와 겹칠 수 없습니다** — 겹치면 프로젝트 생성·편집이 거부됩니다.

## 동기화 충돌과 주의사항

- **충돌 파일 격리**: 동기화 도구가 만든 `*.sync-conflict*`/`(conflicted copy)` 파일은 입력 스캔에서 제외되어 절대 실행·이동되지 않습니다 — 본 릴리스는 스캔에서 제외할 뿐 옮기거나 별도로 집계하지는 않습니다.
- **자가 쓰기 안전성**: ADDE 자신이 노트(상태 마커)를 갱신해도 재전송 루프가 발생하지 않습니다(마커 기반 멱등).
- **동시 편집 주의**: ADDE 가 노트를 갱신하는 정확히 그 순간 같은 줄을 편집하면 동기화 충돌이 날 수 있습니다 — 한 번에 한 기기에서만 능동 세션을 유지하는 것을 권장합니다.

## 민감 정보와 vault 배치

ADDE 가 vault 에 쓰는 모든 것은 설정한 동기화 대상이 됩니다.

| 노트                            | 내용                                                               |
| ------------------------------- | ------------------------------------------------------------------ |
| 승인 노트(`approvals/<req>.md`) | 도구명과 호출 상세 — 실행할 명령 문자열, 파일 경로, 편집 내용 일부 |
| 턴 노트(`turns/<...>.md`)       | 전체 입력과 AI 응답 — 코드 스니펫, 파일 경로, 분석                 |
| 세션/프로젝트 노트              | 턴 미리보기, 상태, 경고                                            |

**vault 로 나가지 않는 것**(동기화 대상 아님): 대화 이벤트 기록의 _원본_ 형태는 vault 의 숨김 `.adde/sessions/<sid>/` 서브트리에 그 세션의 첨부 저장소·중복 판정 원장과 함께 있지만(`vault rebuild` 에 필요), 엔진 진단 로그·메시지 큐·런타임 상태는 `~/.config/adde/` 에만 있습니다. 시크릿은 이벤트 기록이나 노트에 기록되기 **전에** 마스킹(`****`)되지만 — 마스킹은 알려진 시크릿 패턴을 대상으로 하므로, **코드·경로·명령 자체가 민감한** 프로젝트는 노트 내용만으로도 노출될 수 있습니다.

**권장 배치**: 민감한 프로젝트의 vault 서브트리는 동기화 제외 폴더나 별도 로컬 vault 에 두세요. 개인 프로젝트를 팀 공유 vault 에 두지 마세요(승인·턴 노트가 팀 전체에 보입니다).

## 트러블슈팅

증상별 진단·대응은 [트러블슈팅](troubleshooting.ko.md#마크다운-전용) 참조. 권한이 항상 거부되면 기한 전에 allow/deny 중 정확히 하나를 체크했는지 확인하세요.
